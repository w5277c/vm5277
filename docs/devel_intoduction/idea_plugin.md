# Плагин vm5277 для IntelliJ IDEA

## 1. Введение
### 1.1 Цель плагина
Плагин разрабатывается для обеспечения полного цикла поддержки платформы vm5277 (язык j8b) внутри среды разработки IntelliJ IDEA.  
*Примечание: В настоящее время плагин находится в стадии активной разработки, его функционал реализуется постепенно.*

### 1.2 Реализованный функционал
![Интерфейс плагина VM5277 в IntelliJ IDEA с редактором j8b-файла](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_1_2.png)
![Интерфейс плагина VM5277 в IntelliJ IDEA с редактором asm-файла](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_1_2_2.png)
* **GUI-мастер** создания нового проекта vm5277.
* **GUI-конфигуратор** сборки и прошивки проекта vm5277.
* **GUI-прошивальщик** бутлоадера vm5277.
* **Автоматический импорт** и синхронизация Maven-проектов.
* **Интеграция с компонентами vm5277** (компилятор, ассемблер, прошивальщик, Maven-плагин, LSP-сервер).
* **Подсветка синтаксиса** j8b и сгенерированных ASM-файлов.
* **Автодополнение кода** j8b, RTOS и сгенерированных ASM-файлов.

### 1.3 Планируемый функционал
* Поддержка **прошивки фьюзов** (fuse-битов) для AVR.
* **Интерактивная отладка** кода на языке j8b.
* Интеграция с **семантическим анализатором**:
  * Расширенная (контекстная) подсветка кода.
  * Подсветка ошибок компиляции «на лету».
  * Переход к объявлению объектов и по ссылкам.
  * Поиск мест использования объектов (Find Usages).

### 1.4 Системные требования
* **IntelliJ IDEA** (Community или Ultimate) версии **2025.2.6.1** или выше.
* **Наличие интернета** — при первом создании/сборки проекта будет скачан Maven и vm5277 тулкит.  
*Также Maven выполнит загрузку ряда своих библиотек.*
## 2. Установка плагина
1. **Скачайте архив** с плагином с официального сайта по прямой ссылке: [vm5277-idea-plugin-latest.zip](https://vm5277.ru/releases/vm5277-idea-plugin-latest.zip).
2. В IntelliJ IDEA откройте настройки: **Settings** → **Plugins** → иконка шестеренки ⚙️ → **Install Plugin from Disk...**
3. **Выберите скачанный ZIP-файл** и нажмите **OK** (или **Apply**).
4. **Перезапустите IDE**, если среда разработки запросит перезагрузку для активации плагина.


## 3. Создание нового проекта
### 3.1 Мастер создания проекта
1. В IntelliJ IDEA перейдите в меню: **File** → **New** → **Project...**
2. В левой панели выберите категорию **VM5277**.
3. Заполните основные параметры Maven-проекта:
   * **Group ID** — идентификатор группы проекта.
   * **Artifact ID** — имя проекта (идентификатор артефакта).
   * **Version** — версия проекта.
4. Проверьте настройки окружения:
   * **Toolkit path** — путь к установленному инструментарию VM5277.  
   Если тулкит не установлен, поле останется пустым, а рядом появится кнопка для его автоматического скачивания и установки.  
   Нажмите её перед тем, как продолжить.
   * **Maven path** — путь к исполняемому файлу Maven.  
   Если поле пустое, выполните аналогичное автоматическое скачивание по кнопке рядом.  
![Мастер создания проекта VM5277 в IntelliJ IDEA](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_3_1.png)
5. Нажмите кнопку **Next**.
6. На следующем шаге при необходимости скорректируйте параметры:
   * **Project name** — имя проекта в IDE.
   * **Project location** — путь к директории, где будет сохранен проект.
7. Нажмите кнопку **Create** для завершения генерации проекта.

***Важно***, *при первом запуске необходимо немного подождать (несколько минут) в фоне Maven создает проект с помощью архетипа, и скачивает все необходимые зависимости.*  
*Также, вероятно IDEA Вас спросит о загрузке Maven проекта - необходимо ответить утвердительно*. 
### 3.2 Структура создаваемого проекта
После завершения работы мастера будет создана следующая структура директорий:

```text
project/
├── .idea/         # Настройки проекта IntelliJ IDEA
├── prebuild/      # Промежуточные файлы сборки (появляется после первой компиляции)
├── src/
│   └── Main.j8b   # Основной исходный код на языке j8b, созданный из шаблона
├── target/        # Результаты финальной сборки (бинарные файлы)
└── pom.xml        # Конфигурация Maven с подключенным j8b-плагином
```

![Структура файлов проекта VM5277](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_3_2.png)

## 4. Открытие (импорт) существующего проекта
1. Перейдите в меню: **File** → **Open...** и выберите корневую директорию проекта.
2. При первом открытии Maven-проекта IntelliJ IDEA автоматически распознает файл `pom.xml` с настроенным j8b-плагином.
3. Подтвердите импорт проекта в качестве Maven-модели (если среда разработки выдаст соответствующий запрос или предупреждение безопасности **Trust Project**).
4. На основе конфигурации `pom.xml` среда автоматически создаст необходимые служебные файлы в папке `.idea`. 

После завершения синхронизации проект будет полностью активирован и готов к работе.

## 5. Настройка сборки проекта
![Мастер конфигурации сборки проекта VM5277](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_5.png)

1. В правом верхнем углу окна IDE нажмите на выпадающее меню выбора конфигураций (**Current File**) и выберите **Edit Configurations...**
2. Если список конфигураций пуст, нажмите кнопку **+** (**Add New Configuration**) и выберите из списка тип **VM5277 Build & Flash**.
3. Заполните поля формы настроек в правой части окна:
   * **Name** — уникальное имя данной конфигурации запуска.
   * **Toolkit path** — путь к инструментарию VM5277.  
       Если он отсутствует, воспользуйтесь кнопкой автоматического скачивания и установки рядом с полем.
   * **Run mode** — режим выполнения. Выберите один из доступных вариантов:

| Режим (Run mode) | Описание |
| :--- | :--- |
| **Build J8B** | Полная компиляция исходного кода j8b и сборка проекта без прошивки в чип. |
| **Build J8B & Flash** | Полная сборка проекта из j8b и его последующая прошивка в микроконтроллер. |
| **Build J8B & Run** | Полная сборка из j8b, прошивка и автоматический запуск интерактивного режима отладки/мониторинга. |
| **Build ASM** | Сборка бинарного файла прошивки напрямую из ранее сгенерированных ASM-файлов (минуя стадию компиляции j8b). |
| **Build ASM & Flash** | Быстрая сборка из существующих ASM-файлов и прошивка устройства. |
| **Build ASM & Run** | Быстрая сборка из ASM-файлов, прошивка и запуск интерактивного режима. |
   * **CPU Frequency (MHz)** — тактовая частота целевого микроконтроллера в мегагерцах (например, `16`).
   * **Target device** — блок настроек целевого устройства:
     * **Flash vm5277 bootloader** — кнопка для ручной прошивки фирменного бутлоадера VM5277 на подключенный микроконтроллер.
     * **Autodetect** — режим автоматического определения подключенного устройства и его параметров.  
         *Примечание: требует наличия на устройстве предварительно прошитого бутлоадера VM5277.*
     * **Specify target** — режим ручной настройки параметров целевого устройства:
       * **Platform** — выпадающий список поддерживаемых аппаратных платформ (AVR, PIC, STM8 и др.).
       * **Device** — список поддерживаемых моделей микроконтроллеров для выбранной платформы.
       * **STDIO Port(s)** — конфигурация пинов ввода-вывода микроконтроллера.  
           Задается один пин для однопроводного полудуплексного режима или два пина для классического двухпроводного режима.
       * **Flash tool** — выбор утилиты для прошивки целевого устройства.
       * **Download** — кнопка автоматического скачивания выбранной утилиты прошивки (активна, если утилита не обнаружена в системе).  
           *Дополнительно:* ниже динамически отображаются специфические настройки, уникальные для выбранной утилиты прошивки.
   * **Optimization type** — режим оптимизации компилятора:
     * `none` — оптимизация полностью отключена.
     * `front` — применяется только оптимизация на уровне абстрактного синтаксического дерева (AST).
     * `size` — применяется AST-оптимизация и глубокое сжатие генерируемого кода для максимальной экономии Flash-памяти микроконтроллера.
     * `speed` — оптимизация для максимальной скорости выполнения кода. *Находится в разработке (пока не реализовано).*
   * **Strict level** — уровень строгости компилятора при проверке кода:
     * `none` — минимальный контроль качества кода. Предупреждения (warnings) выводятся только в критических случаях.
     * `light` — умеренная проверка кода. Потенциально неоптимальные конструкции вызывают предупреждения, и лишь в исключительных ситуациях — ошибки компиляции.
     * `strong` — максимальная строгость. Большинство предупреждений о неоптимальном или небезопасном коде приводят к ошибке сборки (срабатывает принцип "warnings as errors").
   * **Verbosity** — уровень детализации логов при сборке проекта:
     * `minimal` — вывод только самого важного (ошибки и финальный статус сборки).
     * `normal` — стандартный информационный вывод процесса компиляции.
     * `debug` — расширенный вывод отладочной информации, включая подробные сообщения о настройке и конфигурации ядра RTOS.
   * **Soft reset feature** — программное управление перезагрузкой устройства через бутлоадер VM5277.  
       Опция необходима для плат и аппаратных конфигураций, где микроконтроллер не перезагружается аппаратно при инициализации прошивки.
   * **Bootloader API reuse** — оптимизация размера прошивки.  
       При включении этой опции компилятор исключает из финального бинарника функции, которые уже присутствуют в бутлоадере VM5277, и настраивает вызовы напрямую к коду бутлоадера.
   * **Include addons** — автоматическое подключение дополнительных расширений среды выполнения (runtime) из каталога `vm5277/addons/`.
   * **Maven, quiet** — скрытие служебных и системных сообщений сборщика Maven во время компиляции проекта для очистки лога.
   * **Sync. POM** — принудительная синхронизация конфигурации IntelliJ IDEA с проектом Maven (автоматически обновляет файл `pom.xml` на основе настроек формы).
   * *Примечание:* Если в поле **Flash tool** выбран встроенный прошивальщик (`internal`), становится доступно дополнительное поле:
     * **Interactive mode** — выбор режима интерактивного взаимодействия с устройством:
       * `auto` — автоматическое определение режима на основе активированных функций ядра RTOS.
       * `none` — интерактивный режим отключен (выполняется только прошивка устройства).
       * `output` — режим только вывода (сообщения из микроконтроллера передаются в консоль через UART TX).
       * `full` — полнодуплексный режим ввода-вывода (вывод из UART TX в консоль и передача ввода из консоли в UART RX устройства).
            
## 6. Прошивка бутлоадера
### 6.1 Вкладка Target
![Мастер настройки и прошивки бутлоадера VM5277](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_6.png)

Это основная вкладка для настройки параметров прошивки бутлоадера VM5277 на целевое устройство.
* **STDIO Port(s)** — конфигурация пинов микроконтроллера для связи (используется как для прошивки, так и для интерактивного режима).  
  Бутлоадер использует полностью программную реализацию UART, поэтому он не привязан к конкретным аппаратным выводам интерфейса.  
  Разработчик может задать:
  * *Два пина* (например, `PD0/PD1` для Arduino) — классический вариант, аналогичный аппаратному UART, но занимающий ценные выводы.
  * *Один пин* — для работы в полудуплексном режиме на прием и передачу.
  * *Пин RESET* — если микроконтроллер поддерживает его использование в качестве GPIO (и был прошит соответствующий fuse-бит).
* **Platform** — выбор поддерживаемой аппаратной платформы.  
  *Примечание: На текущий момент реализована поддержка только платформы AVR. Работа над остальными архитектурами начнется после стабилизации основного кода проекта.*
* **Device** — список поддерживаемых моделей микроконтроллеров для выбранной платформы.  
  *Примечание: Как и в случае с платформами, на данном этапе поддерживается ограниченный набор устройств.*
* **Flash tool** — выбор сторонней утилиты, которая будет использована для первоначальной (однократной) прошивки бутлоадера в микроконтроллер.
* **Остальные поля** — состав и назначение этих полей динамически меняются в зависимости от выбранной утилиты прошивки.  
    Их описание можно найти в документации к соответствующей утилите.

### 6.2 Вкладка UID Settings
Бутлоадер VM5277 позволяет хранить в прошивке уникальный идентификатор чипа (UID), что особенно актуально для микроконтроллеров, не имеющих заводского уникального номера.  
На этой вкладке настраивается источник и способ хранения базы данных ваших идентификаторов.  

Доступно три режима генерации и хранения UID:
* **Global (request to server)** — глобальная таблица идентификаторов.  
  В появившихся полях необходимо указать идентификатор разработчика (**Vendor ID**) и пароль (**Password**) для авторизации на удаленном сервере.  
  *Примечание: На стадии альфа-версии проекта серверная часть еще не реализована.*
* **Local (use uids.db file)** — локальная таблица идентификаторов, хранящаяся в виде файла на вашем диске.  
  Путь к файлу базы данных задается в открывшемся поле.
* **Parameter (set manually)** — ручной ввод идентификатора.  
  Конкретное значение UID вносится вручную в появившемся текстовом поле.  
**Дополнительные опции:**
* **Overwrite existing UID** (чекбокс) — разрешает перезапись идентификатора, если в выбранной базе данных такой UID уже существует.

### 6.3 Вкладка Security
Бутлоадер VM5277 поддерживает работу с зашифрованными бинарными файлами: он способен дешифровывать данные прямо «на лету» в процессе прошивки устройства.  
На этой вкладке задаются параметры безопасности:
* **Encryption key** — ключ шифрования.  
Задается в виде 32-байтовой HEX-последовательности (строка шестнадцатеричных символов), которая будет использоваться для дешифрации прошивки.
* **Secure ASM file** — путь к ассемблерному файлу, содержащему алгоритм дешифрации.  
Этот низкоуровневый код компилируется и встраивается непосредственно в тело самого бутлоадера.

### 6.4 Вкладка Advanced
Вкладка содержит дополнительные и экспертные настройки процесса сборки бутлоадера:
* **Generate listing file (bldr.lst)** — генерация файла листинга.  
Перед прошивкой ассемблер компилирует исходный код бутлоадера.  
Включение этой опции позволяет создать отладочный файл листинга (`bldr.lst`), который полезен для анализа сгенерированного ассемблерного кода бутлоадера в случае возникновения проблем.

### 6.5 Вкладка Output
На этой вкладке отображаются итоговые параметры сборки и сгенерированные CLI-команды для прошивки индивидуальной сборки бутлоадера:

* **Toolkit path** — путь к используемому инструментарию VM5277.
* **MKBoot cmd** — автоматически сформированная консольная команда с параметрами для генерации бинарного файла бутлоадера.
* **Flash cmd** — сформированная консольная команда с параметрами для записи бутлоадера в память микроконтроллера.

### 6.6 Запуск прошивки
После настройки всех параметров на вкладках выполните следующие действия:
1. Подключите микроконтроллер к программатору.
2. Нажмите кнопку **Flash device** в нижней части формы.
3. Проанализируйте текстовый вывод в консоли вкладки **Output**.  
![Форма вывода процесса сборки проекта VM5277](https://vm5277.ru/docs/devel_introduction/idea_plugin_img_6_5.png)
Если процесс завершился без ошибок — поздравляем!  
Ваш микроконтроллер успешно прошит фирменным бутлоадером, который обеспечивает гибкую интеграцию со всей экосистемой VM5277.

## 7. Сборка проекта
1. Выберите подходящую конфигурацию запуска в выпадающем меню на панели инструментов.
2. Нажмите кнопку ▶️ **Run** (или воспользуйтесь сочетанием клавиш `Shift + F10`).
3. Запустится процесс сборки, логика и этапы которого зависят от параметров, выбранных вами на этапе настройки конфигурации (раздел 5).

Результаты операции, включая сообщения компилятора и лог работы утилит, выводятся в консоли среды разработки.  
Подробную информацию о специфических логах сторонних утилит можно найти в документации к соответствующему ПО.
 
## 8. Часто задаваемые вопросы (ЧаВо / FAQ)
**В: Обязательно ли использовать IntelliJ IDEA для разработки?**  
**О:** Нет, не обязательно. Вы можете писать код в любом текстовом редакторе и собирать проект через консольные утилиты или Maven. Также существует плагин для NetBeans, но на данный момент он не развивается. В будущем, после полной доработки встроенного LSP-сервера (который пока используется только внутри плагинов для NetBeans и IDEA), появится возможность полноценно использовать любую среду разработки или редактор с поддержкой протокола Language Server Protocol.

**В: Для чего нужен интерактивный режим?**  
**О:** Интерактивный режим — это встроенный функционал прошивальщика, который связывает потоки ввода-вывода микроконтроллера с консолью IntelliJ IDEA. Это позволяет программисту взаимодействовать с устройством (отправлять команды и читать логи через UART) прямо из того окна, где запускалась сборка. Более того, в этом режиме прошивальщик автоматически перехватывает служебный вывод ядра RTOS (например, дампы ошибок или `stacktrace`) и мгновенно преобразует его в человекочитаемый вид.
 
**В: Есть ли недостатки у однопроводного подключения в сравнении с классическим двухпроводным на базе аппаратного UART?**  
**О:** Принципиальных недостатков нет, выбор зависит исключительно от удобства проектирования и отладки вашей платы. Основные различия можно свести к двум факторам:
| Критерий | Однопроводное подключение (Полудуплекс) | Двухпроводное подключение |
| :--- | :--- | :--- |
| **Аппаратное обеспечение** | Требуется отдельный недорогой внешний USB-UART преобразователь. | Можно использовать встроенный на плату USB-порт (например, как на Arduino Uno) или внешний USB-UART преобразователь. |
| **Скорость и режим** | Возможно незначительное падение скорости из-за работы в полудуплексном режиме. | Максимальная скорость обмена данными в полнодуплексном режиме. |

**Итог:** Если аппаратный UART на плате свободен и уже разведен через USB-интерфейс (как на многих готовых отладочных платах), удобнее использовать классическую двухпроводную схему. Если же вам критически важно сэкономить свободные пины микроконтроллера для периферии, однопроводной режим станет отличным решением.

**В: Какой пин лучше всего выбрать для STDIO?**  
**О:** Поскольку подсистема STDIO в микроконтроллере работает через программный UART (реализованный методом bit-banging), для связи можно выбрать абсолютно любой вывод, поддерживающий режим GPIO (а в некоторых моделях микроконтроллеров — даже пин `RESET`). 
При выборе стоит руководствоваться тем, какие выводы гарантированно не будут задействованы в основном функционале вашего устройства. Отличным выбором является пин **SCK**: он часто остается свободным после инициализации периферии и почти всегда удобно выведен на плате в составе интерфейса для прошивки (ISP).
    
**В: Какой BAUDRATE используется для прошивки и почему этот параметр нигде не задается в настройках?**  
**О:** Скорость передачи данных (BAUDRATE) рассчитывается программным UART автоматически и целиком зависит от тактовой частоты микроконтроллера. Поскольку частоту процессора вы в обязательном порядке указываете в поле **CPU Frequency (MHz)** при настройке сборки, каждый компонент системы вычисляет точную скорость самостоятельно.
Зависимость скорости от частоты CPU строго линейная. Чем выше частота, тем выше скорость обмена данными. Примеры автоматического расчета:
* При частоте **16 МГц** скорость составит **230 400** бод.
* При частоте **9.6 МГц** скорость составит **138 240** бод.
* При частоте **8 МГц** скорость составит **115 200** бод.

**О:** Да, архитектура проекта полностью независима от IDE. Плагин для IntelliJ IDEA является лишь графической оболочкой над стандартными инструментами сборки. Вы можете собирать проект альтернативными способами:
* **Через консоль Maven.** Поскольку проект использует стандартный плагин `j8b-maven-plugin`, его можно собрать в терминале стандартной командой (например, `mvn j8b:run -Parduino-uno` или специфической целью плагина). Это привычный и удобный способ для Java-разработчиков.
* **Напрямую через консольные утилиты.** В состав тулкита VM5277 входят все необходимые CLI-инструменты (компилятор, ассемблер и т.д.), на которых и базируется Maven-плагин. Их можно вызывать напрямую из командной строки — они обладают высокой гибкостью, поддерживают подробные флаги настроек и снабжены понятной встроенной справкой (`--help`).
 
**В: Как устроено автоопределение чипа?**  
**О:** Этот функционал обеспечивается глубокой интеграцией прошивальщика и бутлоадера. Процесс автоматического поиска и идентификации чипа устроен следующим образом:
1. **Сканирование портов:** Прошивальщик опрашивает все существующие последовательные (COM) порты на компьютере.
2. **Отправка запроса:** По каждому порту отправляется короткая сигнальная посылка, которую способно распознать ядро бутлоадера.
3. **Переход в режим программирования:**
   * В режиме *Soft reset* работающее ядро RTOS перехватывает эту посылку и программно перезагружает устройство в бутлоадер.
   * В режиме *аппаратного сброса* устройство изначально оказывается в бутлоадере при старте за счет физического ресета.
4. **Идентификация:** Через короткую паузу прошивальщик отправляет основной запрос информации об устройстве. Если порт выбран верно, бутлоадер отвечает и передает хосту все параметры: сигнатуру и UID чипа, конфигурацию портов STDIO, а также тип и версию самого бутлоадера.
5. **Определение топологии линии:** Если во время ожидания ответа прошивальщик получает обратно точную копию своего же запроса, система понимает, что используется однопроводной полудуплексный режим.
Всей собранной от бутлоадера информации полностью достаточно для автоматической конфигурации сборщика и корректной прошивки чипа.
 
**В: Существует ли поддержка других IDE или текстовых редакторов?**  
**О:** На текущий момент ситуация следующая:
* **NetBeans:** Для этой среды существует отдельный плагин. Ранее он был основным инструментом разработки, но из-за отсутствия актуальной документации по API NetBeans его поддержка приостановлена, и сейчас плагин находится в архивном статусе.
* **Другие IDE и редакторы (VS Code и др.):** В качестве фундамента для плагина IntelliJ IDEA сейчас активно разрабатывается библиотека универсального **LSP-сервера** (Language Server Protocol). После завершения её интеграции и стабилизации кода появится возможность подключить полноценную поддержку синтаксиса и автодополнения языка j8b практически в любую современную среду разработки или продвинутый текстовый редактор.
 
**В: Насколько качественно реализован плагин для IntelliJ IDEA в сравнении с остальными компонентами системы?**  
**О:** Плагин распространяется по принципу **«как есть» (AS-IS)**. Моя специализация широка и охватывает множество направлений разработки, однако создание плагинов для сред разработки — это отдельная специфическая ниша. При реализации этого инструмента я отталкивался исключительно от решения прикладных задач проекта, не имея глубокого опыта и специфических знаний в построении сложных расширений для IDE.  
Кроме того, современные среды разработки стремительно меняются: JetBrains регулярно обновляет внутреннее API, из-за чего механизмы плагинов могут ломаться, а ресурсов отслеживать все эти изменения в одиночку нет. На данном этапе плагин представляет собой минимально рабочий инструмент (MVP), который закрывает базовые потребности автоматизации сборки и не более того.
